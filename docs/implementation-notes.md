# Implementation notes (v0.1, Python)

Where the implementation differs from [PLAN.md](PLAN.md), or makes a choice the plan left open:

| Topic | Plan | Implementation | Why |
|---|---|---|---|
| Corpus layout | `corpus/cases/<id>/…` per tool | `corpus/captured/<server>/tools.json` and `corpus/synthetic/<id>.json`, with goldens in `corpus/expected/<target>/<case>.json` | Per-server goldens also cover toolset effects (per-request budgets) and are easier to review. |
| Synthetic goldens | Written by hand before the code | Expected outputs generated by the reference implementation and reviewed. Behaviour for each case was first pinned by hand-written unit tests in `python/tests/`. | The unit tests were the TDD driver; the corpus is the cross-language spec for the TypeScript port. |
| S6 order | T8 → T9 → T5 → T4 | T8 → T5 → T4 → T9, then newly created branches are shaped | T4 and T5 create `anyOf` branches that T9 must see. |
| Evidence types | `recorded` / `probe` / `doc` | Adds `reported` (community reports) and `assumed` (conservative default) | Being honest about weaker evidence instead of labelling it `doc`. |
| Gemini enforcement | Open question | Probed live: `const`, `pattern`, `minLength`/`maxLength`, exclusive bounds, `multipleOf`, `uniqueItems`, `not` and `format: email` are accepted but **not** enforced. `const` → `enum` and integer exclusive → inclusive bounds restore enforcement. | `evidence/probes/gemini-json/*.json` |
| OpenAI / Anthropic verification | Live verdicts | Doc/reported evidence only (no API keys available yet) | See docs/live-verification.md. |
| Hint coverage of `$ref` siblings | — | Not attached where the target forbids keywords next to `$ref` (`hinted: false`) | Attaching them would re-create the rejected shape. |
| `max_nodes` | DoS guard | Counts every JSON value (input and output) | Simple and predictable. |
| Legacy Gemini `parameters` target | Deferred to v0.2 (D3) | Deferred | — |

## TypeScript port (v0.2 work, done ahead of schedule)

- The internal tree uses `Map`s (`SNode extends Map`), so keyword and property order match Python
  exactly. JavaScript objects would move integer-like keys first.
- Python-specific formatting is reproduced for byte-identical report messages: `repr()` of strings,
  `urllib.parse.quote` of `$ref` fragments, and `urljoin` for `$id` resolution (`src/core/pyfmt.ts`,
  `src/core/url.ts`).
- Parity is enforced three ways: all corpus goldens (including argument round-trips, options and
  toolset budgets), 300 committed seeded fuzz cases, and fresh random cases from the Python generator
  on every CI run.
- The port found one bug in the Python reference: a report entry lost its `source_path` when an
  `allOf` merge emptied a node, because a dict subclass is falsy when empty. It was fixed in Python
  and the goldens were regenerated.
